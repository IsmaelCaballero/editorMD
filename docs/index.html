editorMD

Editor Markdown WYSIWYG ligero y multiplataforma (Windows · Ubuntu · Fedora · macOS) con Rust + Tauri 2 + Svelte 5 + Milkdown y arquitectura MVC. Esta página reúne el plan, los pasos dados y lo aprendido en cada uno.

Planificación

Diez fases; cada una termina en una versión SemVer de la app. Pulsa una fase para ver sus tareas. hecho en curso pendiente

Diario de pasos

Cada paso indica qué se hizo, por qué y qué conceptos conviene aprender; los conceptos enlazan a su explicación. El más reciente aparece primero.

Ramas y pull requests

Se usa una rama por feature. Ninguna rama se fusiona en main sin tu aprobación (pull request).

Renombrado al cerrar la fase. Al cerrar cada fase, sus ramas no se borran: se renombran a hecha/F<m>.<n>de<T>/<nombre-original> (m = fase, n = orden del paso dentro de la fase, T = total de pasos de la fase; con ceros a la izquierda si T ≥ 10, p. ej. F1.03de12). Así se ve la secuencia temporal de todo el proceso, no solo el resultado. Ejemplo: feature/F0-scaffold → hecha/F0.1de4/feature/F0-scaffold. n numera pasos (ramas), no tareas del plan.
¿Por qué no se borran las ramas? En un desarrollo normal se recomienda borrar las ramas una vez fusionadas. En este proyecto se conservan deliberadamente: por razones académicas (para mostrar a los alumnos el proceso completo) y por trazabilidad del esfuerzo de desarrollo, ya que en el futuro el trabajo se repartirá entre varios miembros del equipo, cada uno trabajando sobre una parte del sistema con su propio arnés.

Uso de IA y coste

      
Modelo: Claude Opus 5.5 (claude-opus-5-5). Tokens reales medidos en la transcripción de Claude Code con
        scripts/ai-usage.mjs. Coste equivalente a precio de API (con suscripción no se paga por token). Análisis completo y RQ.1 en
        docs/ai-usage/README.md.

      

        
FasePasoEstimación previaLlamadasTokens procesadosCoste eq. USDContexto/llamada

        
      

      
Lección: el 98,6 % de los tokens son relecturas del contexto. El contexto por llamada pasó de 145 k a 485 k tokens a lo largo de la sesión, así que cada fase empezará en una sesión nueva.

    


    
    

      
Arquitectura MVC

      
Variante Passive View. El Modelo está repartido: los servicios del sistema, en Rust; el documento y el formato, en TypeScript. Se comunican por IPC de Tauri.
